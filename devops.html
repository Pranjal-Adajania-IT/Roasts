Git, GitHub, SSH and Docker

Every command has a Copy button. Copy one, paste it into your terminal, press Enter, then move to the next. The numbers show the order within each section.

Replace USERNAME, REPO, Your Name and you@example.com with your own details. The commands are written for Git Bash, Linux, macOS and WSL terminals.

Experiment step by step

Do the experiments in this order: Git, SSH, GitHub, Multiple SSH, then Docker. Steps marked “In the browser” can’t be done from the command line, so do them by hand. Only the essential commands are shown here; the full lists are in the sections below.

Experiment 1: Create a Git repo and commit

Open a terminal (Git Bash, Linux, macOS or WSL) and check that Git is installed.
git --version
Set your name, email and default branch.
git config --global user.name "Your Name" && git config --global user.email "you@example.com" && git config --global init.defaultBranch main
Create a folder and start the repo.
mkdir exp-git && cd exp-git && git init
Create a file, stage it and commit.
echo "Hello Git" > hello.txt && git add . && git commit -m "first commit"
Check the commit.
git log --oneline

Output: one line with a commit ID and “first commit”.

Create a branch, make a change and merge it into main.
git switch -c feature-1 && echo "feature" >> hello.txt && git add . && git commit -m "feature work" && git switch main && git merge feature-1

Output: “Fast-forward” is printed. Experiment 1 is done.

Experiment 2: Create an SSH key and connect it to GitHub

Check that SSH is installed.
ssh -V
Generate a key.
ssh-keygen -t ed25519 -C "you@example.com"

Press Enter three times to accept the default path and skip the passphrase.

Start the SSH agent and add the key.
eval "$(ssh-agent -s)" && ssh-add ~/.ssh/id_ed25519
Print the public key and copy the whole line.
cat ~/.ssh/id_ed25519.pub

The line starts with ssh-ed25519 and ends with your email.

In the browser, open github.com. Click your profile photo, then Settings, SSH and GPG keys, New SSH key. Enter a title (for example My Laptop), paste the key and click Add SSH key.
Test the connection.
ssh -T git@github.com

Type yes the first time. Output: Hi USERNAME! You’ve successfully authenticated. Experiment 2 is done.

Experiment 3: Push a repo to GitHub

In the browser, go to github.com and click New repository. Name it REPO, leave README and .gitignore unticked, and click Create repository.
In the terminal, go to the folder from Experiment 1.
cd exp-git
Add the remote and push.
git branch -M main && git remote add origin git@github.com:USERNAME/REPO.git && git push -u origin main
In the browser, refresh the repo page.

Output: hello.txt is listed, along with the commit count.

Clone the repo into a new folder to prove it really is on GitHub.
cd .. && git clone git@github.com:USERNAME/REPO.git exp-clone && ls exp-clone

Output: hello.txt is listed. Experiment 3 is done.

Experiment 4: Multiple SSH keys (personal and work)

Have both GitHub accounts ready, personal and work. You will need to log in to each.
Generate two separate keys.
ssh-keygen -t ed25519 -C "personal@example.com" -f ~/.ssh/id_ed25519_personal -N "" && ssh-keygen -t ed25519 -C "work@example.com" -f ~/.ssh/id_ed25519_work -N ""
Add both keys to the agent.
eval "$(ssh-agent -s)" && ssh-add ~/.ssh/id_ed25519_personal ~/.ssh/id_ed25519_work && ssh-add -l
Print the personal public key.
cat ~/.ssh/id_ed25519_personal.pub
In the browser, add this key to your personal GitHub account (same as step 5 of Experiment 2).
Print the work public key.
cat ~/.ssh/id_ed25519_work.pub
In the browser, add this key to your work GitHub account.
Create the config file. Copy the whole cat >> ~/.ssh/config block from the Multiple SSH section in one go and paste it, then run this.
chmod 600 ~/.ssh/config
Test both connections.
ssh -T git@github-personal; ssh -T git@github-work

Output: a Hi message with your personal username first, then your work username. The ; is deliberate: GitHub’s test returns exit code 1 even on success, so && would skip the second test.

When cloning, use the Host name instead of github.com.
git clone git@github-work:ORG/REPO.git

Experiment 4 is done.

Experiment 5: Run an HTML form in Docker

Start Docker Desktop (Windows or macOS), then run the test image.
docker run hello-world

Output: Hello from Docker!

Create a folder.
mkdir docker-form && cd docker-form
Run the three cat commands from the Docker form section: index.html, style.css and Dockerfile. Then check the files.
ls

Output: Dockerfile, index.html and style.css should all be listed.

Build the image.
docker build -t form-site .
Start the container.
docker run -d -p 8080:80 --name form-container form-site
In the browser, open http://localhost:8080. The form appears.
Check that the container is running.
docker ps

Output: form-container is listed with Up status.

Clean up when you’re done.
docker rm -f form-container

Experiment 5 is done.

If you get an error

  • Permission denied (publickey): the key isn’t added on GitHub, or ssh-add wasn’t run. Run ssh-add again and check the key on GitHub.
  • Could not resolve hostname github-work: the Host name in ~/.ssh/config is wrong, or the config wasn’t saved.
  • remote origin already exists: run git remote set-url origin git@github.com:USERNAME/REPO.git.
  • port is already allocated: 8080 is busy. Use -p 8081:80 and open localhost:8081.
  • permission denied (Docker on Linux): put sudo in front of the command.

Git basics

Install check, one-time setup and everyday commands.

git --version

If a version number appears, Git is installed.

git config --global user.name "Your Name"
git config --global user.email "you@example.com"
git config --global init.defaultBranch main
git config --list
mkdir my-project && cd my-project
git init
echo "# My Project" > README.md
git status
git add .
git commit -m "first commit"
git log --oneline

Branch and merge

git switch -c feature-1

Creates a new branch and switches to it. Edit a file here, then add and commit.

git branch
git switch main
git merge feature-1
git branch -d feature-1

Fixing mistakes

git diff
git restore FILE_NAME

Discards the uncommitted changes in that file.

git reset --soft HEAD~1

Undoes the last commit and keeps the changes staged.

git stash
git stash pop

GitHub

First create a new empty repo on github.com (don’t add a README). You need an SSH key set up, which is covered in the next section.

git branch -M main
git remote add origin git@github.com:USERNAME/REPO.git
git remote -v
git push -u origin main
git pull origin main
git fetch origin
git push origin feature-1

After pushing a branch you can open a Pull Request on GitHub.

Getting a repo onto your machine

git clone git@github.com:USERNAME/REPO.git
cd REPO
git remote set-url origin git@github.com:USERNAME/NEW_REPO.git

Use this when you need to change the remote URL.

SSH key (one account)

Create a key once, add it to GitHub, and pushes work without a password.

ssh -V
ssh-keygen -t ed25519 -C "you@example.com"

Press Enter at the path prompt. The passphrase is optional.

eval "$(ssh-agent -s)"
ssh-add ~/.ssh/id_ed25519
cat ~/.ssh/id_ed25519.pub

Copy the full output. On GitHub go to Settings, SSH and GPG keys, New SSH key, and paste it.

ssh -T git@github.com

Type yes the first time. If you see Hi USERNAME!, it worked.

SSH into a server

ssh user@SERVER_IP
ssh-copy-id user@SERVER_IP
ssh -i ~/.ssh/KEY_NAME user@SERVER_IP

Multiple SSH (personal and work)

Two GitHub accounts, two separate keys, one config file. The -f flag gives each key its own file name.

ssh-keygen -t ed25519 -C "personal@example.com" -f ~/.ssh/id_ed25519_personal
ssh-keygen -t ed25519 -C "work@example.com" -f ~/.ssh/id_ed25519_work
eval "$(ssh-agent -s)"
ssh-add ~/.ssh/id_ed25519_personal
ssh-add ~/.ssh/id_ed25519_work
ssh-add -l
cat ~/.ssh/id_ed25519_personal.pub

Add this one to your personal GitHub account.

cat ~/.ssh/id_ed25519_work.pub

Add this one to your work GitHub account.

cat >> ~/.ssh/config << 'EOF' Host github-personal HostName github.com User git IdentityFile ~/.ssh/id_ed25519_personal IdentitiesOnly yes Host github-work HostName github.com User git IdentityFile ~/.ssh/id_ed25519_work IdentitiesOnly yes EOF

This is a single command, so copy the whole block at once.

chmod 600 ~/.ssh/config
ssh -T git@github-personal
ssh -T git@github-work

Using the repos

git clone git@github-personal:USERNAME/REPO.git

Write the Host name in place of github.com. That is the whole trick.

git clone git@github-work:ORG/REPO.git
git remote set-url origin git@github-work:ORG/REPO.git

Use this to switch the account of a repo you already cloned.

git config user.name "Work Name"
git config user.email "work@example.com"

Run these only inside that repo so its commits carry the right identity.

Docker: run an HTML form

A plain HTML and CSS form served from an nginx container. There is no backend, so the form uses mailto and opens your mail app to send the message.

docker --version
docker run hello-world

This checks that Docker is working.

mkdir docker-form && cd docker-form
cat > index.html << 'EOF' <!DOCTYPE html> <html lang="en"> <head> <meta charset="UTF-8"> <meta name="viewport" content="width=device-width, initial-scale=1"> <title>Contact Form</title> <link rel="stylesheet" href="style.css"> </head> <body> <form action="mailto:you@example.com" method="post" enctype="text/plain"> <h1>Contact us</h1> <label>Name <input type="text" name="name" required></label> <label>Email <input type="email" name="email" required></label> <label>Message <textarea name="message" rows="4" required></textarea></label> <button type="submit">Send message</button> </form> </body> </html> EOF

Replace you@example.com with your own email.

cat > style.css << 'EOF' body{font-family:Arial,sans-serif;background:#f2f4f8;display:grid;place-items:center;min-height:100vh;margin:0} form{background:#fff;padding:24px;border-radius:8px;width:320px;display:grid;gap:12px} label{display:grid;gap:4px;font-size:14px} input,textarea{padding:8px;border:1px solid #ccc;border-radius:4px;font:inherit} button{padding:10px;border:0;background:#2563eb;color:#fff;border-radius:4px;cursor:pointer} EOF
cat > Dockerfile << 'EOF' FROM nginx:alpine COPY . /usr/share/nginx/html EOF
docker build -t form-site .
docker run -d -p 8080:80 --name form-container form-site

Open http://localhost:8080 in your browser.

Managing the container

docker ps
docker logs form-container
docker stop form-container
docker start form-container
docker rm -f form-container

After editing the HTML or CSS, run this command, then build and run again.

docker images
docker rmi form-site

Push to Docker Hub (optional)

docker login
docker tag form-site DOCKERHUB_USERNAME/form-site:latest
docker push DOCKERHUB_USERNAME/form-site:latest
